# 01 需求分析

> 版本：v1.0 ｜ 状态：待评审

## 1. 项目背景与目标

秋招季时间跨度长（7 月～12 月）、投递量大（几十到上百家）、流程节点多（网申 → 测评 → 笔试 → 多轮面试 → Offer），仅靠 Excel 或笔记难以：

- 实时掌握「还有多少家在流程中、卡在哪一轮、哪些快到截止日期」；
- 回顾每一家的完整时间线；
- 统计自己的投递→面试→Offer 转化漏斗。

**目标**：打造一个单用户、本地运行、打开即用的秋招进度实时追踪应用，把"投了什么、进展如何、接下来该做什么"一屏看清。

**非目标**：不做求职社区、不做个性化推荐算法、不做多用户云服务（均列为远期扩展）；爬虫仅用于「发现职位 → 导入追踪」，不抓取面经/笔试答案等内容；邮件分析仅读取招聘相关候选邮件，用户可随时关闭。

## 2. 用户画像与场景

- **画像**：应届毕业生/求职者，计算机使用熟练度中等，习惯网页操作。
- **核心场景**：
  1. 早上打开首页 → 看「今日提醒」（今天的笔试/面试/截止日期）；
  2. 投递了新公司 → 快速录入，标记优先级；
  3. 收到笔试/面试通知 → 修改状态、设置提醒时间；
  4. 每周复盘 → 看趋势图与漏斗，调整投递策略；
  5. 拿到 Offer/被拒 → 更新状态，时间线自动留痕；
  6. 暂无明确目标 → 数据源页按关键词抓取牛客网职位，挑选感兴趣的一键导入追踪；
  7. 邮箱堆积大量笔试/面试/感谢信邮件 → 邮件分析页一键分析，确认后自动生成时间线与提醒。

## 4. 核心业务流程

### 4.1 投递状态机（F4 的核心）

```
                  ┌────────────┐
                  │  WISHLIST  │ 待投递（初始）
                  └─────┬──────┘
                        │ 已投递
                        ▼
                  ┌────────────┐
                  │  APPLIED   │ 已投递
                  └─────┬──────┘
        ┌───────────────┼───────────────────┐
        │ 简历通过       │ 笔试通知           │ 挂/无回应
        ▼               ▼                   ▼
  ┌────────────┐  ┌──────────────┐   ┌────────────┐
  │ SCREENING  │─▶│ WRITTEN_TEST │   │  REJECTED  │
  └─────┬──────┘  └──────┬───────┘   └────────────┘
        └────────────────┼──────────────┐
                         │ 笔试通过       │ 笔试挂
                         ▼               ▼
                  ┌─────────────┐  ┌────────────┐
                  │ INTERVIEW_1 │  │  REJECTED  │
                  └─────┬───────┘  └────────────┘
                        │ 通过
                        ▼
                  ┌─────────────┐
                  │ INTERVIEW_2 │
                  └─────┬───────┘
                        │ 通过
                        ▼
                  ┌─────────────┐
                  │ INTERVIEW_3 │
                  └─────┬───────┘
                        │ 通过
                        ▼
                  ┌──────────────┐
                  │ HR_INTERVIEW │
                  └──────┬───────┘
                         │ 通过
                         ▼
                  ┌────────────┐
                  │   OFFER    │
                  └─────┬──────┘
                 ┌──────┴───────┐
                 │ 接受          │ 拒绝
                 ▼              ▼
          ┌────────────┐  ┌────────────┐
          │   SIGNED   │  │  REJECTED  │
          └────────────┘  └────────────┘

补充规则：
- 任意非终态 → REJECTED（被拒）/ WITHDRAWN（主动放弃）均允许；
- REJECTED / SIGNED / WITHDRAWN 为终态，不可再流转（提供「重新打开」恢复为 APPLIED）；
- 面试轮次可用 INTERVIEW_1/2/3 顺序推进，也可跳轮（如直接 HR 面）。
```

### 4.2 状态→提醒联动

- 状态流转到 `WRITTEN_TEST` / 面试各轮时，前端引导用户一键创建对应提醒（可跳过）；
- 申请存在未完成的过期提醒时，在列表页给出视觉提示。

### 4.3 数据录入流程

```
录入公司（或从已有公司选择）
  → 录入岗位/投递信息（渠道、JD 链接、截止日期）
  → 初始状态 WISHLIST 或 APPLIED
  → 后续通过「状态流转」按钮推进
```

### 4.4 爬虫发现 → 导入追踪流程

```
选择数据源（牛客网）→ 输入关键词（如「后端」）+ 类型（校招/实习）+ 页数
  → 服务端限速抓取职位列表，归一化为待导入记录
  → 前端预览表格（公司/岗位/薪资/城市/JD 链接），支持勾选与去重提示
  → 导入选中项 → 走统一 ImportService 管线（校验、公司查重、申请去重、入库）
  → 在申请列表继续推进状态

自动化增强（v1.1）：
  - 「抓取后自动导入」开关：抓取完成直接入库（F17）
  - 定时任务：应用运行期间每分钟检查，到期自动执行以上全流程并记录运行历史（F15）
```

### 4.5 邮件智能分析流程

```
设置页配置：邮箱 IMAP（服务器/账号/授权码）+ LLM（DeepSeek API Key，可选）
  → 邮件分析页点击「分析最近 N 天邮件」
  → 服务端 IMAP 拉取 → 关键词规则初筛招聘相关候选邮件 → message-id 去重
  → 逐封调用 LLM 提取结构化信息（公司/事件类型/时间/岗位/摘要/置信度）
    （未配置 Key 时降级为本地规则提取，置信度标记为低）
  → 前端卡片列表：邮件原文摘要 + 提取结果，支持编辑修正
  → 「应用」：匹配公司 → 生成时间线笔记事件 + 未来时间自动建提醒
    （状态变更仍由用户通过状态机确认，邮件仅做建议）
```

### 4.6 官网投递追踪流程

```
申请表单选择渠道「官网」→ 粘贴 JD 链接 → 点击「解析」自动预填岗位名/公司/描述
  → 初始状态 WISHLIST → 投递后手动推进 APPLIED
  → 官网后续通知一般走邮件 → 由 4.5 邮件分析自动捕获进展
```

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 单用户、≤ 3000 条申请数据时，列表/看板接口 P95 < 300ms；前端首屏 < 3s（本地） |
| 数据安全 | SQLite 单文件存储；删除公司/申请为软交互（确认弹窗）；导出功能保障数据可迁移 |
| 可用性 | Chrome/Edge 现代浏览器 + 响应式布局（桌面为主，兼容窄屏）；全中文界面 |
| 可维护性 | 前后端 TypeScript；后端分层（路由/控制器/服务/数据层）；前端组件化 |
| 安全与隐私 | 邮箱授权码与 LLM API Key 仅存本地 SQLite，接口返回脱敏；邮件内容仅在用户主动触发分析时发送给所选 LLM；Excel 导出不包含任何配置信息 |
| 可扩展性 | 数据接入层抽象统一接口，新增数据源不改动核心业务代码 |

## 6. 约束与假设

- 单用户、本地运行，无需认证与权限体系；
- 时间统一使用本地时区，存储为 ISO 8601 字符串；
- 招聘状态语义以校招通用流程建模，不针对特定公司定制。

## 7. 范围外（远期扩展）

- Boss直聘/拉勾等强反爬平台的稳定适配器（v1 仅提供实验性方案，见文档 06 §6）；
- 多用户与云同步、主动推送提醒（短信/微信/邮件通知）；
- 求职资料（简历版本、面经笔记）管理模块。
